Цель — построить воспроизводимый ML-пайплайн и сравнить три модели классификации изображений на исходных данных и данных с аугментацией.

## Текущее состояние

Настроены Git, DVC и Docker-окружение. Выполнены полные эксперименты трёх моделей на исходных данных Fashion-MNIST. Добавлен отдельный этап воспроизводимой аугментации с проверкой происхождения записей. Выполнены эксперименты на исходном и расширенном наборах, результаты сравнены на валидации. Итоговая оценка на тесте и оформление отчёта выполняются отдельно.

## Docker-окружение

Требуется Docker Desktop с Linux-контейнерами. Образ рассчитан на Linux/amd64.

В Compose описан один сервис `app`. Он содержит Python 3.13.16, Git, DVC, NumPy, SciPy, scikit-learn, Matplotlib, Pillow и PyYAML. Базовый образ закреплён по digest, версии Python-пакетов и их контрольные суммы находятся в `requirements.lock`.

Папка проекта подключается к контейнеру как `/workspace`. Изменения кода, история Git/DVC, данные и результаты сохраняются в этой папке после завершения контейнера. Локальное окружение Windows `.venv` не используется как Python-окружение внутри контейнера.

По умолчанию контейнер проверяет окружение и завершает работу. Для этих команд используется `docker compose run --rm`.

## Подготовка данных

Используется [Fashion-MNIST от Zalando](https://github.com/zalandoresearch/fashion-mnist), распространяемый под лицензией MIT: 60 000 исходных обучающих изображений и 10 000 тестовых, 10 классов одежды.

Исходная обучающая часть разделяется по классам с фиксированным seed 42:

| Выборка | Всего изображений | На каждый класс |
| --- | ---: | ---: |
| Обучающая | 50 000 | 5 000 |
| Валидационная | 10 000 | 1 000 |
| Тестовая | 10 000 | 1 000 |

Тестовые изображения, метки и их порядок сохраняются как у авторов. Подготовленные выборки сохраняются без изменений; аугментированная обучающая часть создаётся отдельно.

- `data/raw/` содержит четыре исходных gzip-файла.
- `data/prepared/train.npz`, `validation.npz`, `test.npz` содержат массивы `images`, `labels`, `source_ids`.
- Изображения имеют форму `(N, 28, 28)` и тип `uint8`. Нормализация выполняется при обучении и предсказании.
- `source_ids` сохраняет номер исходной записи. Для официальной тестовой части используются ID от 60 000 до 69 999.
- `data/prepared/summary.json` хранит размеры выборок, распределение классов и контрольные суммы.

Загрузчик проверяет официальные MD5 каждого исходного файла, повторяет загрузку при сетевой ошибке и не сохраняет повреждённые результаты. Для подготовленных файлов также вычисляются SHA-256.

Параметры разделения находятся в `params.yaml`. Размер валидации задаётся количеством примеров каждого класса. В каждом классе должен оставаться хотя бы один обучающий пример.

### Проверка уже подготовленных данных

В текущей рабочей папке данные подготовлены и проверены. Новые скрипты доступны контейнеру через подключённую папку проекта; зависимости Docker-окружения не менялись.

```powershell

```

Проверка данных должна вывести `"status": "ok"`, размеры 50 000 / 10 000 / 10 000, `"source_id_overlap": 0` и `"official_test_unchanged": true`. Нулевое пересечение относится к исходным записям по их ID.

### Загрузка и воспроизведение подготовки

Если исходных данных ещё нет, загрузите их. Проверенные файлы повторно не скачиваются:

```powershell
docker compose run --rm app python scripts/prepare_data.py download
docker compose run --rm app dvc add data/raw
docker compose run --rm app dvc repro prepare
docker compose run --rm app python scripts/prepare_data.py check
docker compose run --rm app dvc push
```

Этап `prepare` описан в `dvc.yaml`. DVC отслеживает скрипт, исходные данные и параметры разделения. Если ничего не изменилось, подготовленные файлы используются из кэша. Для намеренного повторного выполнения:

```powershell
docker compose run --rm app dvc repro --force prepare
```

Сравнение хешей при повторной подготовке выполнено в локальном окружении с NumPy 2.5.4. Проверка `check` дополнительно сверяет все изображения и метки с исходными записями и проверяет соответствие seed.

## Обучение и проверка моделей

Добавлены три классификатора scikit-learn:

- `logreg` — логистическая регрессия с решателем L-BFGS.
- `random_forest` — случайный лес.
- `mlp` — полносвязная нейронная сеть с одним скрытым слоем по умолчанию.

Изображение 28 × 28 разворачивается в 784 признака. Пиксели переводятся из `uint8` в `float32` и делятся на 255. Для логистической регрессии и MLP дополнительно применяется `StandardScaler`. Он обучается только на обучающей выборке и сохраняется вместе с классификатором. При проверке используются уже рассчитанные параметры нормализации.

Пайплайн обучения на исходных данных включает три последовательных этапа:

1. `prepare`: проверка исходных данных и подготовка выборок.
2. `train`: обучение выбранной модели и сохранение её состояния.
3. `evaluate`: предсказания и метрики на валидационной выборке.

Тестовая выборка на этом этапе не используется. Выбор модели и настройка параметров выполняются по валидации; итоговая оценка на тесте будет добавлена после фиксации экспериментов.

### Параметры

В `params.yaml` задаются модель, seed и параметры трёх классификаторов. При обычном запуске `train.limit_per_class: 0` означает весь выбранный обучающий набор: 50 000 изображений для prepared или 100 000 для augmented. Положительное значение выбирает указанное число исходных записей каждого класса с фиксированным seed; в режиме augmented сохраняются также все их копии. Валидация при обычном запуске содержит все 10 000 изображений.

DVC отслеживает секцию `train` и все три секции параметров моделей. Изменение любой из этих секций делает этап обучения неактуальным. Неверные типы, неизвестные параметры, отрицательные значения и нечисловые значения для числовых параметров приводят к понятной ошибке.

Вычисления ограничены одним потоком, чтобы уменьшить различия между повторными запусками. Для MLP отключена внутренняя ранняя остановка: внешняя валидация остаётся отдельной выборкой. Время обучения зависит от компьютера.

### Короткая проверка

Образ пересобирать не нужно: зависимости не менялись, новые файлы доступны через подключённую папку проекта.

```powershell

В режиме prepared это 200 обучающих изображений; в режиме augmented с одной копией это 400 изображений вместе с преобразованными вариантами. Для неё отдельно уменьшены число деревьев, размер скрытого слоя и число итераций. Результаты сохраняются только в `results/smoke/`, игнорируются Git и DVC и не заменяют основные результаты. `params.yaml` и `dvc.lock` не изменяются.

### Полное обучение выбранной модели

Когда требуется полный эксперимент на исходных данных:

```powershell
docker compose run --rm app dvc exp run -n original-logreg-next -S train.dataset=prepared -S train.model=logreg evaluate
docker compose run --rm app dvc exp show -A
Get-Content ./metrics/validation.json
docker compose run --rm app dvc push
```

Имя эксперимента должно быть свободным. Для других моделей используются `train.model=random_forest` и `train.model=mlp` с отдельными именами экспериментов. Результаты выполненного сравнения приведены ниже. Цель evaluate ограничивает запуск пайплайном исходных данных.

Во время обучения каждые 15 секунд выводится сообщение о том, что вычисления продолжаются. Не прерывайте процесс из-за отсутствия промежуточных метрик.

Если на полном обучении возникает `ConvergenceWarning`, запуск сохраняет результат и предупреждение. Проверьте `models/current/training.json`: при необходимости увеличьте `max_iter` и выполните отдельный эксперимент. Флаг `converged` означает отсутствие предупреждений о сходимости, а не достижение заданного качества.

### Результаты

- `models/current/model.joblib` — классификатор, обученный нормализатор, параметры и ID обучающих записей.
- `models/current/training.json` — параметры, размер обучения, версии библиотек, контрольные суммы, время и предупреждения.
- `metrics/validation.json` — accuracy, macro-F1, размеры выборок, время обучения и флаг сходимости.

Модель, числовые метрики и подробные результаты хранятся в кэше DVC. Числовые метрики объявлены в DVC как `metrics` с `cache: true`, поэтому восстанавливаются вместе с моделью. Git хранит их контрольные суммы и описание эксперимента. DVC связывает результат с кодом, параметрами и версиями данных.

Перед оценкой проверяются контрольная сумма модели, версии библиотек и отсутствие пересечения ID обучения и валидации. Формат подготовки пикселей записан в метаданных модели. Файл `joblib` следует загружать только из доверенной копии результатов проекта.

Для возврата к сохранённому эксперименту:

```powershell

docker compose run --rm app python scripts/model.py evaluate
```

После применения восстанавливаются параметры, модель и результаты эксперимента. Повторная команда `evaluate` проверяет, что сохранённая модель пригодна для предсказаний. Восстановление требует наличия соответствующих файлов в кэше DVC или его хранилище.

## Аугментация обучающих данных

Этап `augment` читает подготовленные выборки и создаёт отдельный набор для дальнейшего обучения. По умолчанию к каждому исходному обучающему изображению добавляется одна копия со случайной комбинацией преобразований:

- отражение по горизонтали с вероятностью 0,5;
- поворот на угол от −10 до +10 градусов;
- сдвиг по каждой оси на целое число от −2 до +2 пикселей.

Поворот и сдвиг выполняются с линейной интерполяцией и чёрным заполнением за границами изображения. Размер 28 × 28 и тип `uint8` сохраняются. Реализация использует [SciPy rotate](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.rotate.html) и [SciPy shift](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.shift.html).

Новый обучающий набор содержит 100 000 изображений: 50 000 исходных и 50 000 преобразованных. В каждом классе будет 10 000 изображений. Валидация и тест остаются в исходной подготовленной папке без изменений, по 10 000 изображений.

Параметры находятся в секции `augmentation` файла `params.yaml`. Случайное преобразование определяется seed, ID исходной записи и номером копии. Поэтому один и тот же пример получает одинаковое преобразование независимо от порядка обработки и размера выбранного поднабора.

Проверяются типы и диапазоны: seed от 0 до 4294967295, от 1 до 10 дополнительных копий, угол от 0 до 45 градусов, максимальный сдвиг от 0 до 7 пикселей, вероятность отражения от 0 до 1. Все преобразования одновременно отключать нельзя. Параметры по умолчанию используют небольшие изменения; увеличение диапазонов может ухудшить различимость изображений и качество моделей.

## Обучение на расширенном наборе

Параметр `train.dataset` выбирает обучающие данные:

- `prepared` — 50 000 исходных обучающих изображений.
- `augmented` — 100 000 изображений: исходные и сохранённые преобразованные копии.

DVC подставляет значение в путь зависимости `data/${train.dataset}`. При выборе расширенного набора перед обучением проверяются контрольные суммы, параметры аугментации, сохранность исходных изображений, метки и происхождение копий. Подробная проверка `augment_data.py check` дополнительно пересчитывает все преобразованные пиксели.

Валидация в обоих режимах выполняется на одних и тех же 10 000 исходных изображений. Тестовые изображения не используются для обучения, выбора модели или расчёта приведённых метрик.

Положительный `train.limit_per_class` ограничивает число исходных записей каждого класса. В режиме `augmented` вместе с выбранной исходной записью остаются все её преобразованные копии. Значение 0 использует полный набор.

Для новых полных экспериментов используются следующие команды. Имена должны быть свободными; существующие эксперименты сохраняются в истории:

```powershell
docker compose run --rm app dvc exp run -n augmented-logreg -S train.dataset=augmented -S train.model=logreg -S train.limit_per_class=0 evaluate
docker compose run --rm app dvc push

docker compose run --rm app dvc exp run -n augmented-random_forest -S train.dataset=augmented -S train.model=random_forest -S train.limit_per_class=0 evaluate
docker compose run --rm app dvc push

docker compose run --rm app dvc exp run -n augmented-mlp-300 -S train.dataset=augmented -S train.model=mlp -S train.limit_per_class=0 -S mlp.max_iter=300 evaluate
docker compose run --rm app dvc push

docker compose run --rm app dvc exp show -A --csv
```

Параметры моделей и seed сохраняются как в исходных экспериментах: логистическая регрессия с лимитом 2000 итераций, случайный лес из 100 деревьев, MLP со скрытым слоем из 128 нейронов. Для итоговой пары MLP установлен одинаковый лимит 300 эпох; первоначальные запуски с лимитом 100 сохранены отдельно. Успешное выполнение команды и отсутствие предупреждений о сходимости проверяются отдельно.

В метаданных модели записываются выбранный набор, число исходных и новых изображений, число уникальных родительских записей и параметры аугментации. Прежние модели остаются пригодны для оценки.

docker compose run --rm app dvc exp show -A --csv

## Итоговая тестовая оценка и графики

Модель выбирается по macro-F1 из сохранённого сравнения на валидации. Этап `freeze` сверяет параметры, seed, обучающий набор и валидационные метрики текущей модели с выбранным экспериментом, затем сохраняет её отдельную копию в `models/selected/`. Файл `selection.json` содержит имя и ревизию эксперимента, основание выбора и контрольные суммы. На этом этапе тестовая выборка не читается.

Этап `test` использует зафиксированные веса и все 10 000 официальных тестовых изображений. Он проверяет контрольные суммы модели и отсутствие пересечения ID с обучением. Метрики сохраняются в `metrics/test.json`; подробности и предсказания — в `reports/test_details.json` и `reports/test_predictions.npz`. Доступный в Git итог с параметрами и происхождением модели находится в `results/final_test.json`.

Этап `plots` создаёт четыре рисунка в `results/figures/`:

- `validation_quality` — accuracy и macro-F1 на исходном и расширенном наборах;
- `training_time` — наблюдаемое время обучения;
- `test_confusion_matrix` — матрица ошибок выбранной модели на тесте;
- `test_class_f1` — F1 по каждому классу на тесте.

Для каждого рисунка сохраняются PNG с разрешением 300 dpi и векторный SVG. Графики и краткий итоговый JSON отслеживаются Git, большие результаты и веса — DVC.

Полный запуск заключительных этапов:

```powershell
docker compose run --rm app dvc repro plots
docker compose run --rm app dvc status
docker compose run --rm app dvc push
```

Если модель и данные актуальны, обучение пропускается. Повторная оценка зафиксированных весов без обучения:

```powershell
docker compose run --rm app python scripts/finalize.py test
```

Снимок `results/validation_comparison.json` описывает выбор модели до тестовой оценки. Его поле `test_evaluated: false` относится к моменту выбора; актуальные тестовые результаты записываются отдельно в `results/final_test.json`. Итоговое качество на тесте не используется для изменения выбора или настройки параметров.

## Хранилище данных DVC

Настроено локальное хранилище `.dvc-storage/` внутри папки проекта, отдельно от кэша `.dvc/cache/`. Оно доступно и Windows, и контейнеру через относительный путь в `.dvc/config`.

```powershell
docker compose run --rm app dvc push
docker compose run --rm app dvc status -c
```

После сохранения файлов ожидается `Cache and remote 'local' are in sync.`

GitHub содержит код и метаданные DVC, а сами наборы данных и `.dvc-storage/` в Git не отправляются. Для восстановления в другой папке или на другом компьютере нужно отдельно перенести хранилище в корень новой копии проекта и выполнить `dvc pull` либо заново загрузить исходные данные и воспроизвести этап `prepare`.

Это локальное хранилище на том же компьютере, а не облачная резервная копия.

## Управление версиями

Git хранит код, настройки, документацию и метаданные DVC. DVC отслеживает наборы данных и после обучения — модели и подробные результаты. Кэш DVC и локальное окружение Python не входят в Git.

Настроено локальное хранилище DVC. Одна копия репозитория GitHub не содержит сами данные и модели.

```powershell
git status
git remote -v
docker compose run --rm app dvc version
```

Обычные Git-коммиты и отправка на GitHub выполняются на компьютере пользователя. DVC создаёт локальные коммиты экспериментов внутри контейнера. В текущем репозитории имя и почта Git сохранены в локальной настройке .git/config и доступны контейнеру через подключённую папку. Эти настройки не входят в Git. В новой копии репозитория перед первым экспериментом задайте свои значения через git config --local user.name и git config --local user.email. Команда dvc push сохраняет файлы в локальное хранилище; Git push не отправляет туда файлы моделей или сами ссылки экспериментов DVC.

## Зависимости

- `requirements-dvc.txt` фиксирует DVC для локальных вспомогательных команд.
- `requirements.in` описывает прямые зависимости Docker-окружения.
- `requirements.lock` содержит разрешённые зависимости для Python 3.13.16 и Linux/amd64, включая транзитивные зависимости и хеши файлов. В Docker используется именно этот файл.

Для пересоздания файла фиксации при намеренном изменении зависимостей требуется uv:

```powershell
uv pip compile requirements.in --python-version 3.13.16 --python-platform x86_64-manylinux_2_36 --generate-hashes --default-index https://pypi.org/simple --output-file requirements.lock
```

После обновления файла фиксации нужно пересобрать и проверить образ.

## Локальное окружение DVC

Основной способ работы — через Docker. Для команд DVC без Docker можно использовать отдельное локальное окружение Python:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dvc.txt
.\.venv\Scripts\dvc.exe version
.\.venv\Scripts\dvc.exe status
```

Если локальное окружение уже создано на первом этапе, повторять установку не требуется. Активация окружения необязательна.
