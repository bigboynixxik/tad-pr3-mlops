# TAD PR3 MLOps – версионирование данных и моделей

Практическая работа № 3 по дисциплине «Технологии анализа данных».

## Цель

Построить воспроизводимый ML-конвейер и сравнить три модели классификации изображений на исходных данных и данных с аугментацией, сохраняя версии данных, моделей и экспериментов с помощью Git и DVC.

## Что сделано

Используется [Fashion-MNIST](https://github.com/zalandoresearch/fashion-mnist): 70 000 изображений одежды и обуви размером 28 × 28 пикселей, 10 классов. Данные разделены на 50 000 обучающих, 10 000 валидационных и 10 000 тестовых изображений с seed 42.

- Настроено Docker-окружение с закреплёнными версиями зависимостей.
- Один DVC-пайплайн выполняет весь цикл: подготовка → три модели параллельно → аугментация → три модели параллельно → сравнение → фиксация лучшей модели → тест → графики.
- Для каждого обучающего изображения создана одна копия с отражением, поворотом и сдвигом. Расширенный train содержит 100 000 изображений; validation и test не изменяются.
- Каждая модель работает в отдельном процессе и сохраняет собственные веса, метрики и журнал. Один DVC-эксперимент содержит все шесть вариантов; выполнены автоматические проверки, подготовлены метрики и графики.
- Модель выбрана по macro-F1 на validation, зафиксирована в `models/selected/` и отдельно оценена на test.

## Команды для запуска

Требуется Docker Desktop с Linux-контейнерами. Команды PowerShell выполняются из корня проекта.

**Сборка и восстановление готового результата:**

```powershell
docker compose build app
docker compose run --rm app
docker compose run --rm app dvc pull
docker compose run --rm app dvc repro plots
```

Вторая команда проверяет окружение. `dvc pull` восстанавливает данные и модели, а **`dvc repro plots` одной командой выполняет весь пайплайн**. Внутри каждого этапа обучения запускаются три процесса; следующая группа начинается после завершения предыдущей и подготовки аугментации. Актуальные этапы пропускаются или восстанавливаются из кэша.

Для демонстрации с повторным обучением всех шести моделей:

```powershell
docker compose run --rm app dvc repro --force plots
```

DVC-хранилище в этом проекте локальное: `.dvc-storage/`. Для восстановления готовых результатов после клонирования репозитория нужно отдельно перенести эту папку в корень проекта. GitHub хранит код и метаданные, а данные и модели в Git не входят.

**Если исходные данные не перенесены, их можно загрузить и подготовить:**

```powershell
docker compose run --rm app python scripts/prepare_data.py download
docker compose run --rm app dvc repro prepare
```

Это создаёт выборки для обучения, но не восстанавливает готовые модели и историю экспериментов.

**Сохранить общий запуск как новый DVC-эксперимент:**

```powershell
docker compose run --rm app dvc exp run -n parallel-new plots
```

Имя после `-n` должно быть новым. Параметры каждой модели находятся в `params.yaml`; например, `-S mlp.alpha=0.001` изменяет регуляризацию MLP. Общий пайплайн всегда обучает все три модели на обоих наборах и требует `train.limit_per_class=0`. Поля `train.model` и `train.dataset` оставлены для вспомогательных одиночных запусков и не ограничивают общий цикл.

**Просмотр локальной истории и восстановление полного запуска:**

```powershell
docker compose run --rm app dvc exp show -A
docker compose run --rm app dvc exp apply parallel-six
```

`exp apply` меняет рабочее состояние; перед ним сохраните собственные правки. Именованные эксперименты передаются отдельно через `dvc exp push` и `dvc exp pull`; обычный `git clone` не получает их локальную историю.

Модели находятся в `models/parallel/{prepared,augmented}/{model}/`, метрики – в `metrics/parallel/`, журналы и интервалы обучения – в `reports/parallel/`. В `run.json` каждой группы поля `max_parallel_fits` и `three_way_fit_overlap_seconds` показывают фактическое пересечение вызовов обучения.

**Проверки:**

```powershell
docker compose run --rm app python -m unittest discover -s tests -v
docker compose run --rm app dvc status
```

## Модели и эксперименты

- **Логистическая регрессия** – линейный классификатор, предел 2 000 итераций.
- **Случайный лес** – ансамбль из 100 деревьев решений.
- **MLP** – полносвязная нейросеть с одним скрытым слоем из 128 нейронов, предел 300 эпох.

В одном запуске сравниваются шесть вариантов: каждая модель обучается на исходном и расширенном train. Внутри каждой пары совпадают параметры модели, seed и валидационная выборка. Ниже приведены результаты на validation из 10 000 изображений.

| Модель | Accuracy исходные | Accuracy с аугментацией | Macro-F1 исходные | Macro-F1 с аугментацией |
| --- | ---: | ---: | ---: | ---: |
| Логистическая регрессия | 0,8459 | 0,8243 | 0,844735 | 0,822548 |
| Случайный лес | 0,8879 | 0,8795 | 0,886477 | 0,877236 |
| MLP | 0,8924 | 0,8794 | 0,891773 | 0,878213 |

Выбранная аугментация снизила качество всех трёх моделей. Лучший вариант по macro-F1 – **prepared/mlp**, MLP на исходных данных. На отдельном тесте из 10 000 изображений получены **accuracy 87,89 %** и **macro-F1 0,878206**. При пределе 300 эпох выбранная модель завершила обучение за 74 эпохи. Идентификатор варианта записан в `selection.candidate_id`, а версия всего запуска доступна через историю DVC.
